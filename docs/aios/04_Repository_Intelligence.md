# 46. PROJECT INTELLIGENCE

The repository SHALL continuously describe its own condition.

An AI agent shall never rely on intuition to determine
whether the project is healthy.

Project health must be measurable.

Every execution SHALL improve at least one health metric.

---

# 47. HEALTH DIMENSIONS

Project health is composed of independent dimensions.

Repository Health

Documentation Health

Knowledge Health

Creative Health

Architecture Health

Implementation Health

Testing Health

Production Health

Overall Health

No single metric represents project quality.

Overall Health SHALL be derived from
weighted component metrics.

# 57. DEBT MANAGEMENT SYSTEM

Debt is any known deficiency that
reduces future production quality.

Debt SHALL be documented.

Debt SHALL be prioritized.

Debt SHALL never be hidden.

---

# 58. DEBT TYPES

Technical Debt

Architecture Debt

Documentation Debt

Knowledge Debt

Creative Debt

Testing Debt

Experience Debt

Production Debt

New debt categories MAY be introduced
when justified.

---

# 59. TECHNICAL DEBT

Examples

Temporary workaround

Duplicated logic

Poor abstraction

Hardcoded values

Unused modules

Incomplete refactoring

Technical debt SHALL include

Reason

Impact

Risk

Recommended resolution

Priority

---

# 60. DOCUMENTATION DEBT

Examples

Missing architecture

Missing README

Outdated API docs

Unexplained workflow

Undocumented decision

Undocumented dependency

Documentation debt SHALL never be ignored.

---

# 61. KNOWLEDGE DEBT

Knowledge Debt exists whenever
repository understanding is incomplete.

Examples

Unknown requirement

Missing story explanation

Missing timeline event

Undefined asset ownership

Incomplete character motivation

Unknown production dependency

Knowledge debt is HIGH priority.

Unknown knowledge creates future errors.

---

# 62. CREATIVE DEBT

Creative Debt exists whenever
the intended emotional experience
cannot yet be delivered.

Examples

Dialogue placeholder

Missing transition

Incomplete scene

Temporary narration

Missing soundtrack plan

Missing cinematic cue

Creative debt SHALL never be confused
with implementation progress.

---

# 63. EXPERIENCE DEBT

Experience Debt measures unfinished
player experience.

Examples

No onboarding

Broken emotional pacing

Abrupt scene transition

Missing feedback

Weak interaction

Incomplete immersion

Experience Debt directly impacts quality.

---

# 64. ARCHITECTURE DEBT

Architecture Debt exists whenever
current architecture limits future growth.

Examples

Circular dependency

Unclear ownership

Improper module boundaries

Missing abstraction

Fragile design

Architecture Debt accumulates silently.

Continuous review is required.

---

# 65. TESTING DEBT

Testing Debt includes

Untested systems

Missing regression tests

Unverified edge cases

No validation plan

Missing acceptance criteria

Testing debt SHALL be visible.

Invisible testing debt is unacceptable.

---

---

# 69. CONTINUOUS IMPROVEMENT

Each execution SHALL improve
at least one of the following

Health

Debt

Risk

Documentation

Knowledge

Architecture

Implementation

Testing

If none improved,

the execution produced no measurable value.

---

# 70. DEFINITION OF PROJECT MATURITY

A mature repository is not one that
contains the most code.

A mature repository is one where

knowledge is preserved,

decisions are traceable,

dependencies are explicit,

architecture is understandable,

creative intent is documented,

and any qualified engineer
can continue production
without external explanation.
